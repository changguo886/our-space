# Our Space V4 — Execution planning UI v2

Status: implementation in progress on feature/v4-todo-ui. Do not claim release-ready without Next.js build and browser tests.

## Principles
1. Todo identity, scheduling intentions and actual completions/focus are separate. No fabricated focus or completion events.
2. Routine creation remains optional without execution appointments.
3. Planning starts from selecting dates, not from saving one session and copying it repeatedly.
4. Weekday quick actions: Workdays (Mon–Fri), Weekend (Sat–Sun). No Mon/Wed/Fri preset; users choose arbitrary days.
5. Fixed Routine rule days are suggested and highlighted; rules do not prevent extra dates. Flexible weekly/monthly goals never create quota-matched appointments automatically.
6. Shared fixed/window/flexible timing applies to chosen dates; independent per-day edits are allowed before saving.
7. Explicit save scope: current period creates dated todo_sessions; recurring creates virtual todo_execution_templates. Each weekday/month-day has an independent slot_key generated by database. No future mass materialization.
8. Dates in the past and dates before the task start are unavailable for newly planned sessions. Historical completions and focus remain untouched.
9. No automatic conversion of completion goals when creating recurring timing.
10. Editing a real dated Session updates its id; a virtual occurrence is identified by todo_id, slot_key, occurrence_date and changed with an Override. Stop future via stop_execution_template_future_v3; don't delete past records.

## UI architecture
- Create/Edit Todo: parent task fields and completion rule through save_task_v4; planning panel remains optional and may appear after Todo creation.
- TodoExecutionSchedule: existing records management, one-off exceptions, future-series changes; launch the new RoutinePlanComposer for Routine planning.
- RoutinePlanComposer: select dates, workdays/weekend shortcuts, shared time, per-day fine-tuning, save once for this period or repeatedly. Monthly selection uses date grid. Fixed rules default select their eligible dates, flexible quota has none selected.
- Day/Week/Month: select date to navigate and select individual appointment to manage. Overlap groups list exact task titles and estimated effort.
- Journey: keep journey-day notes distinct from calendar appointment management.

## Known gaps before release
- Unified one-off and virtual occurrence editor in every calendar view; monthly repeat identity and complex overrides.
- A true transaction-safe batch-save RPC or database uniqueness/locking; browser-side overlap checks alone cannot prevent racing writes.
- Same-day multiple slots on the same weekday require distinct slot identity and independent editing. Current composer supports one slot per selected day, not multiple.
- CalendarPlanner state refresh after changing a one-off appointment and using the window layer.
- Task create/edit form integration beyond existing Todo workspace.
- Supabase RLS, cascade-delete and save/stop RPC signatures must be checked against live DB read-only metadata.
- Build, lint, typecheck, browser tests, and rollback plan are required before merge. Do not merge to Main unapproved.

## Verification checklist
- Weekly fixed Mon/Wed/Fri: autofill eligible future weekdays and customize each time, save current-week only versus continuing series.
- Weekly flexible quota three: no forced selection; workday/weekend buttons and arbitrary dates.
- Monthly fixed/flexible: selecting 29/30/31 and month-end behavior, crossing year boundaries.
- Fixed/window/flexible per-day override; prevention of duplicate or overlapping dated sessions.
- Create, edit, cancel one, stop future; ensure history untouched.
- Day/Week/Month selection retains the selected date; no jump back to today.
